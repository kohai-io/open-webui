- `OPENAI_API_KEY`

These names are classified as unchanged, but fresh values must be selected for the new deployment. In particular, wildcard CORS is not an acceptable production default.

The v0.10.2 example additionally documents `ENABLE_MEMORY_SYSTEM_CONTEXT` and the `VALKEY_*` vector-store settings. They are new optional configuration, not required legacy replacements.

## Compose-level variables

The primary legacy and v0.10.2 Compose files use the same interpolation names:

- `OLLAMA_DOCKER_TAG`
- `OPEN_WEBUI_PORT`
- `WEBUI_DOCKER_TAG`

The primary container environment still sets `OLLAMA_BASE_URL` and `WEBUI_SECRET_KEY`. Production must pin `WEBUI_DOCKER_TAG` to the tested release/image digest and supply the secret through the deployment's secret-management mechanism rather than committing it.

Other Compose overlays reference host/runtime names such as GPU settings, ports, home/data directories, and CLI arguments. Their use in the actual deployment is unknown until the live Compose command and selected overlays are recorded.

## Staging configuration rules

1. Start from the v0.10.2 example and source defaults, not a copied legacy environment.
2. Select fresh values only for required integrations.
3. Keep all secret values in the existing secret-management system.
4. Pin release images by digest; do not deploy `main` or an unpinned floating tag.
5. Set explicit production CORS origins, proxy trust, callback URLs, and public base URL.
6. Record the final variable names and their owners, never their values, beside this matrix.
